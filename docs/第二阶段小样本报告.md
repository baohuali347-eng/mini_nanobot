# 第二阶段真实模型小样本记录

2026 年 11 月 2 日，沿用第一阶段的 `deepseek-flash` 和内置 `clamp_and_slug`。每种模式独立运行一次，预算保持每次 18 次调用 / HTTP 请求、150 秒。第二阶段启用最多两次业务修复与一次格式更正，额度由全部角色、格式更正和业务修复共享。

供应商用量覆盖率为 100%。所有失败均保留在报告中，预算未突破。Agent 耗时扣除中间验收，逐轮记录单独保存实际验收耗时；全部角色退出后又进行了最终外部复核。

并行模式中，探索角色首次交接格式不合规，记录到一次 `purpose=report_repair` 的模型调用，成功整理为有效交接后启动实现角色。这次更正计入 18 次总预算，没有执行更正响应中的工具。随后一个实现角色触及上限，系统停止而非无限重试；虽然最终代码通过验收，工作流仍不计成功。

本次三种模式没有发生业务修复：单 Agent 首轮通过；串行遇到执行错误，未重新执行原 DAG；并行虽未完成报告，但最终代码通过，且模型预算已耗尽。业务修复能力通过独立的故障回归验证：首次错误声明完成 → 实际验收失败 → 带失败反馈修改真实文件 → 第二次实际验收通过，同时保留首轮失败和共享调用计数。该回归的模型使用替身，不冒充真实模型成绩。

## 真实运行发现并修复的边界

串行探索角色在若干只读工具调用后返回空的最终答复。运行时原先在进入格式校验前直接报错，因此没有使用本次配置的一次格式更正。

本次原始记录后已补齐此边界：有格式更正额度时，最终空答复也允许整理交接；保留已完成的工具组，不重做原工作；更正不提供工具，模型仍返回工具调用则直接拒绝。连续空答复、额度耗尽和空消息不能进入下一次请求的情况均加入回归测试。普通主 Agent 的非结构化空答复仍报错，不自动当作子任务交接处理。

原始报告与当时的引擎哈希保持不变；这项边界修复只做离线回归，没有追加未经授权的真实模型运行。因此表中的串行结果代表修复前的那次真实运行，不能描述为修复后的实测成功。

## 与第一阶段的关系

第一阶段单 Agent 正常完成，串行因审查交接格式无效未完成，并行因审查预算不足未完成。第二阶段本次观察到格式更正实际生效，也发现了空答复的新边界。两次均只有一个任务、每种模式一次，模型轨迹不同，且引擎版本改变，不能据此声称提高总体成功率或获得并行加速。

后续扩大对比时应固定任务集和相同总预算，重复运行，分别观察首轮成功率、最终成功率、格式更正开销、业务修复次数和预算耗尽比例。每次修复不会重新分配完整预算。
