# 本地接口与配置

## HTTP 接口

所有 API 使用 JSON。除登录外，需要 HttpOnly 的 `mini_access` Cookie；访问码由终端登录链接提供，不要分享。服务仅绑定 `127.0.0.1`，拒绝其他网站发来的 Origin。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/login` | 用 `{ "token": "访问码" }` 登录 |
| `GET /api/status` | 查看模型名称、配置状态和默认目录，不返回密钥 |
| `GET /api/sessions` | 会话列表 |
| `POST /api/sessions` | 用 `{ "workspace": "代码目录" }` 创建会话 |
| `GET /api/sessions/{id}` | 消息、状态和最近 100 条活动 |
| `POST /api/sessions/{id}/chat` | 发送 `{ "message": "任务" }`，返回逐行 JSON 事件流 |
| `POST /api/sessions/{id}/stop` | 停止主任务、子任务和命令 |
| `GET /api/sessions/{id}/memory` | 读取该项目的长期记忆 |
| `PUT /api/sessions/{id}/memory` | 用 `{ "content": "完整记忆" }` 保存记忆 |

事件类型：`text` 是回复片段，`history` 是已保存的用户/助手消息，`round` 是模型轮次，`tool` 是工具活动，`task` 是子任务状态，`model` 是模型请求追踪，`compaction` 是上下文压缩，`integration` 是补丁组合与发布，`validation` 是后端验收，`repair` 是业务修复，`report_repair` 是交接格式更正，`error` 是中文错误，`done` 是最终会话快照。刷新页面后可以查询会话状态，页面断开不自动重放请求。

`model` 事件含调用归属、span/request ID、耗时与供应商用量，不包含密钥或完整请求体。事件追踪字段、评测命令与指标口径见 [评测与追踪](评测与追踪.md)。

## 多 agent 任务计划与交接

这是主 agent 调用的工具协议，网页使用自然语言即可，不需要手写 HTTP 请求。原有 `create/check/send/cancel` 继续可用。存在依赖时使用 `plan`：

```json
{
  "action": "plan",
  "wait": true,
  "tasks": [
    {
      "id": "explore", "role": "explorer",
      "task": "阅读 calculator.py，定位加法错误，不修改文件。",
      "depends_on": [], "acceptance": ["指出问题位置与修复建议"]
    },
    {
      "id": "implement", "role": "coder",
      "task": "只修改 calculator.py，修复错误并运行加法断言。",
      "depends_on": ["explore"], "acceptance": ["修复加法逻辑", "实际运行断言并报告结果"]
    },
    {
      "id": "review", "role": "reviewer",
      "task": "读取修改后的源码和前置交接，独立审查逻辑与验证证据。",
      "depends_on": ["implement"], "acceptance": ["报告具体问题或无发现，以及审查范围"]
    }
  ]
}
```

每次用户请求最多 12 个子任务（包括 `create` 创建的任务）。ID 为英文字母开头的 1～40 位字母、数字、下划线或短横线，在该请求的同一执行轮次内唯一；全部修复轮次合计仍最多 12 个子任务。允许引用本计划后面定义的任务，也可引用本请求已有任务。验收要求为 1～6 项，每项最多 200 字符。后端先完整校验，再启动；不存在的依赖、自依赖与循环都会拒绝整批计划。

`wait=true` 等待整批结束并返回概览；`false` 立即返回，主 agent 可继续独立工作。无前后依赖的任务按并发上限运行，等待依赖不占名额。前置出现 error、cancelled、blocked 或 needs_followup 时，下游标记 blocked，不调用模型。失败后由主 agent 判断后续方案，可用新 ID 创建后续计划；已阻断节点不在原 DAG 内重启；配置后可由后端在新的执行轮次中限次修复。`send` 只向等待或运行中的节点补充说明。

计划中的子任务最终输出必须符合以下格式：

```json
{"outcome":"completed","summary":"已修正加法并运行断言。","unresolved":[]}
```

`outcome` 只能是 `completed` 或 `needs_followup`；摘要最多 2400 字符，未解决问题最多 6 项、每项 300 字符。有未解决问题时，即使自报 completed 也会标为 needs_followup；交接格式错误在限次格式更正仍无效时标为 error；评测默认关闭更正以保留基线。探索发现下游应修复的缺陷属于探索成果，写入摘要，不代表探索本身失败。

下游自动接收前置的交接对象。主 agent 调用 `{"action":"check","task_id":"implement"}` 可读取同一对象：

| 字段 | 来源与含义 |
| --- | --- |
| `task_id`、`role`、`status`、`depends_on`、`acceptance` | 后端保存的计划与状态 |
| `reported_outcome`、`summary`、`unresolved` | 角色自报，不能视为机器自动验收 |
| `files_changed` | 文件工具成功写入的项目内路径；不含命令产生的文件变化 |
| `checks` | 命令工具记录的原始命令、目录、真实退出码、超时标记及输出 |
| `validation` | 可信后端验收结果、规则与产物哈希；未指定验收 ID 时为 not_configured |
| `artifact`、`write_paths` | 实际补丁摘要与写入范围；不等于补丁已发布，完整记录另存后端 |
| `evidence_truncated` | 交接证据是否限长；最多 12 条文件路径和最近 6 条命令，单条输出保留 600 字符 |

没有执行命令时 checks 为空，模型口头声称“测试通过”不会生成执行证据。文件路径和命令记录不能通过子任务最终 JSON 伪造；添加额外字段会校验失败。命令非零退出码按原样记录，不会被后端改为通过；它是否满足验收仍需角色和主 agent 判断。

task 事件增加 `run_id`、`depends_on`、`acceptance` 和终态 `handoff`，不同轮请求的同名任务使用 run_id 区分。tool 事件带执行证据。刷新后从 SQLite 会话事件读取，接口返回最近 100 条活动；证据更早时仍保存在数据库。任务图调度只属于本次进程内请求，重启不自动续跑。可信验收 ID、自动修复及版本核对见 [验收与有限修复](验收与有限修复.md)；副本隔离和冲突保护见 [隔离与补丁集成](隔离与补丁集成.md)。

## 配置字段

沿用 `~/.mini_nanobot/config.json` 的核心结构，完整默认文件可以用 `init` 生成。

| 字段 | 用途与默认值 |
| --- | --- |
| `agents.defaults.model` | 模型名称，示例 `deepseek-flash` |
| `agents.defaults.provider` | 读取哪个连接配置，默认 `custom` |
| `providers.custom.apiBase` | OpenAI 兼容模型地址 |
| `providers.custom.apiKey` | 建议填写 `${MINI_NANOBOT_API_KEY}`，不写真实密钥 |
| `agents.defaults.maxToolIterations` | 最大执行轮数，默认 40 |
| `agents.defaults.maxConcurrentSubagents` | 子任务并发上限，默认 4 |
| `isolateSubagents` | 子任务独立副本，默认 true；false 仅保留共享模式 |
| `allowSubagentDeletes` | 是否允许合规补丁删除原文件，默认 false |
| `maxModelCalls` | 全部角色与修复共享的模型调用及 HTTP 请求上限，默认 60 |
| `maxOutputTokens` | 单次模型输出上限，对应 API 的 max_tokens，默认 8192，允许 1～65536 的整数；服务商可另有限制 |
| `runTimeout` | 普通聊天总执行秒数，含验收与修复，默认 600 |
| `validation.commands` | 可信验收命令与产物路径，默认空，不从模型输出加载 |
| `validation.maxRepairAttempts` | 业务修复次数，0～2，默认 2 |
| `validation.reportRepairAttempts` | 格式更正次数，0～2，默认 1 |
| `contextBudget` | 粗略上下文预算，默认 24000 |
| `streamUsage` | 是否请求流式 Token 用量，默认 `true`；不支持该选项的兼容接口可设 `false` |
| `tools.exec.timeout` | 命令最大运行秒数，默认 120 |
| `tools.exec.sandbox` | 空字符串表示应用层检查；可指定 `seatbelt` 或 `bwrap` |
| `tools.exec.sandboxRoBinds` | 沙箱额外允许读取的绝对目录 |
| `tools.exec.sandboxRwBinds` | 沙箱额外允许修改的绝对目录 |

配置 `${变量名}` 必须有对应环境变量，不支持 Shell 默认值语法。环境变量先于 `.env`。指定沙箱后，后端缺失或启动失败不会降级执行；第三方工具安装目录可能需要显式只读授权。

单次输出上限与上下文预算、总调用上限独立。默认 8192 与本轮修复后复测配置一致，可在配置顶层用 `maxOutputTokens` 覆盖。增加上限可能增加单次请求用量，服务商也可能限制可用值。

思考模型可能在输出正文或工具请求前用完输出额度，此时会明确停止并提示 `maxOutputTokens`，保留此前的工具结果。工具请求被截断时也会停止，避免执行部分工具。普通文本截断保留原有最多两次续接机制。模型每轮会收到当前共享请求剩余额度提示，所有角色、摘要和重试仍受同一个硬预算约束。

评测时可用 `--max-output-tokens 8192` 显式固定本轮上限，覆盖配置值并记录到 manifest，便于不同版本对照。

旧渠道、自动化、远程服务、OAuth 和自更新字段不参与运行。旧版 WebUI 的端口和认证设置不再沿用；端口使用 `web --port`，本机访问码保存在独立 `mini_web_token` 文件。
